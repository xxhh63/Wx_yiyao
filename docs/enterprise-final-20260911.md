# 我是企业：最终分类与后端交接

日期：2026-09-11。依据用户提供的最终企业思维导图。小程序修改、编译与验证由独立任务“云开发路线”负责。

本次复用现有分类字典、原生管理表单和内容接口，无新增依赖。企业默认打开“技术”；一级分类仅保留下面六项，删除分类栏“全部”和排序筛选。每个筛选的“不限”只用于清除条件；图中明确列出的“其他”选项保留。

## 技术

- **交易意向**：产出、诉求。
- **技术领域**：小分子、抗体、多肽、类器官、基因与细胞治疗、其他领域。
- **研发阶段**：早期研究、临床前研究、临床研究、申请上市、批准上市。
- **合作模式**：技术转让、技术授权、其他模式。

## 专利

- **专利类型**：发明专利、实用新型专利、软著。
- **专利领域**：小分子、抗体、多肽、类器官、基因与细胞治疗、其他领域。
- **专利状态**：有效授权、实质审查中、即将过期。
- **合作模式**：专利转让、专利授权、其他模式。

## 保存与筛选规则

- 交易意向复用资源必填的供需类型：产出对应 supply，诉求对应 demand；它已有业务含义，不新增另一份字段。
- 其余分类属性均可留空。发布后可在该专栏看到；选定具体筛选条件后，空值不会匹配。组合条件按 AND 查询。
- 企业编辑表单只展示最终图的选项，不把旧选项补回下拉框。图外选项退出企业筛选，不删除真实资源、正文或其他专区关联。
- 原生搜索、分页、资源版本冲突检查、上架下架、其他角色分类和首页统计口径沿用现有实现。

## 接口与存储

继续使用 GET /api/catalogs/enterprise、GET /api/resources?audience=enterprise&category=... 及原有管理 CRUD 接口。分类键依次为 technology、patent、mah、data、talent、service。查询参数使用字典 filter.key；读取和编辑属性必须使用 filter.field（缺省为 key），不要硬编码旧字段。

| 查询参数 | JSON 属性 |
| --- | --- |
| technologyField | enterpriseTechnologyField |
| researchStage | enterpriseResearchStage |
| cooperationMode | enterpriseCooperationMode |
| patentField | enterprisePatentField |
| mahType | enterpriseMahType |
| approvalStatus | enterpriseApprovalStatus |
| tradeMode | enterpriseTradeMode |
| dataType | enterpriseDataType |
| complianceMaturity | enterpriseComplianceMaturity |
| talentType | enterpriseTalentType |
| serviceType | enterpriseServiceType |
| qualification | enterpriseQualification |

kind 保存在资源根字段；patentType、patentStatus、talentMaturity 的定义与原有其他角色一致，继续复用原属性，保证专利与专家计数一致。其他发生定义变化的企业属性独立保存，避免覆盖同一资源在科研或投资人专区的资料。

preservedFiltersByCategory 仅用于验证及保留历史共享属性，不是可显示的企业筛选配置。内部保留空的 filtersByCategory.all 兼容旧请求，不在分类栏暴露。

## 数据库升级

**无需改表结构。需要执行新增的 migration/004_enterprise_categories.sql，为既有企业资源补充新 JSON 属性。** 不要重新运行 000～003，也不要重新导入演示数据。

1. 在数据库客户端明确选中现有业务库 yiyao，核对当前连接后执行 SELECT DATABASE();。脚本没有 USE，也不会新建数据库。
2. 在新的查询连接中完整执行 004，客户端设置遇到错误立即停止；发生错误时在同一连接 ROLLBACK，不手工补 COMMIT。
3. 成功后末尾返回企业各分类的记录条数。脚本不会删除记录，也不会把未填写的新属性猜成临床、合规或资质结论。
4. 已有新属性（包括主动清空的空字符串）不覆盖；仅补缺失属性，首次补充会增加内容 version。可重复执行，已完成行不再次修改。

迁移只复制新字典允许的原值，并处理以下明确对应关系；不能确定的旧值保留在历史属性，新属性留空，后续由管理员确认填写。

| 原值 | 新企业值 |
| --- | --- |
| 专利全权转让 | 专利转让 |
| 独占许可、排他许可、专项授权使用 | 专利授权 |
| CRO服务、CDMO服务 | CXO服务 |
| 丰富落地案例 | 丰富案例 |
| 单项项目外包 | 单项目合作 |

冻结的 phase2-source.json / phase2-manifest.json 用于旧内容追溯。export-phase2.cjs 不再用旧快照覆盖当前运行字典。
