# 登录与单选身份标签

## 已确认的交互

- 未登录打开小程序，自动显示自定义登录提示。微信手机号快速验证授权只能由用户点击原生授权按钮触发。
- 用户关闭后，除关闭按钮与协议/隐私链接外，其他点击再次显示登录提示。
- 登录成功但尚未设置身份时，进入资讯、项目等业务内容先显示身份选择；保存成功后继续原目标。
- 四选一：我是企业、我是科研院所、我是投资人、我是服务机构。用户已明确将多选更正为单选。
- “我的”显示当前身份并可修改；服务端成功后更新显示，失败保留原身份。重新打开、换设备和重登以服务端为准，换账号不能沿用上个用户的标签。
- 标签是用户自行选择的偏好，不是企业/科研资质认证，也不授予管理员权限。本期不实现推荐算法。

## 接口

小程序继续使用自建 HTTPS 服务。新增接口沿用 `X-Auth-Token` 与统一 `ApiResponse`，不接受客户端指定 userId、appid 或 openid。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/me/identity` | 获取当前用户身份；首次未选择返回 null |
| PUT | `/api/me/identity` | 保存或替换当前用户唯一身份 |

PUT 请求只允许一个 tag 字段：

```json
{"tag":"enterprise"}
```

| tag | label | 前端选项 |
| --- | --- | --- |
| enterprise | 企业 | 我是企业 |
| scientist | 科研院所 | 我是科研院所 |
| investor | 投资人 | 我是投资人 |
| manager | 服务机构 | 我是服务机构 |

manager 沿用现有服务机构专区的内部标识。不要为显示名称更改资源分类 key。

GET / PUT 成功响应示例：

```json
{"code":0,"errorMsg":"","data":{"tag":"enterprise","label":"企业","savedAt":"2026-09-18T00:00:00Z"}}
```

尚未选择时 data 为 `{"tag":null,"label":"","savedAt":null}`。空标签、多选数组、非法标签及额外字段返回 400；未登录或会话失效返回 401，手机号未授权返回 428。返回头 `Cache-Control: no-store`。无标签不会破坏登录或名片接口。

前端在已有会话恢复或登录成功后读取身份。读取失败、接口尚未部署、保存失败均不能伪装选择成功；保存操作不能在失败后自动替用户选择默认身份。登录响应结构保持原样，避免与手机号授权流程耦合。

## 数据与更新顺序

新增 `app_user_identity`：user_id 主键并关联 app_user；tag 保存唯一身份；saved_at 保存最后修改时间。同一用户修改采用覆盖保存，不追加第二条身份。通过 app_user 的 (appid, openid) 定位用户，避免跨账号/跨小程序串写。不会改 user_card 或 app_user_phone，不回填默认身份。

现有服务器业务库先核对 `SELECT DATABASE();` 为目标库，再执行 `migration/007_user_identity.sql`。该增量仅创建新表，可重复执行，不清空现有数据。初始化空库可使用已包含该表的 `src/main/resources/schema-mysql.sql`。

更新顺序：增量 SQL → 后端 JAR → 检查身份 API → 小程序前端。SQL 不会随 Spring Boot 自动执行；Git 推送不等于服务器部署。现有公共内容接口保持不变，登录与身份提示用于小程序交互，不将自报身份当作资源访问权限。

## 验收要求

后端检查未登录拒绝、初始空标签、四项单选、非法输入、单选覆盖、用户隔离、会话失效、重启恢复和名片不受影响。前端检查启动弹窗、关闭后任意点击、协议放行、登录后选择、保存失败重试、我的修改及账号切换时的过期响应隔离。模拟接口测试与真实手机号授权/真机操作分别记录。
