# 资源管理：角色与分类联动

日期：2026-09-09。

## 使用流程

资源列表先按四个角色模块切换，再选择该模块的二级分类；搜索、分页和新建资源沿用当前模块与分类。另有“查看全部资源”入口，保留仅首页主推及项目池资源的管理能力。

| 一级模块 | 二级分类 |
| --- | --- |
| 投资人 | 项目、MAH、场景 |
| 企业 | 人才、技术、专利、MAH、数据、服务机构 |
| 科学家/科研院所 | 人才、技术、专利、数据、服务机构；投融资保留未开放状态 |
| 技术经理人 | 成果 |

新建/编辑顺序为：一级模块 → 二级分类 → 三级分类（选填）→ 资源内容。使用现有 catalog-schema.json 的角色专属选项，不混合其他角色的同名字段选项。排序方式不是三级属性。

例如投资人/项目展示项目类型、最高研发阶段、适应症赛道。全部可留空，适应症可多选及清空。标题等原有必填内容仍须填写。

## 空属性与已有内容

- 保存后仍是草稿，发布后进入所选专栏。三级属性全部为空不阻止保存和发布。
- 无具体筛选时可找到该资源；某一具体筛选值只匹配已填写对应值的资源，多条件保持 AND 关系。
- 同一资源可在“其他展示设置”中勾选支持该类型的其他专区，仍只存一个资源主记录。
- 编辑已有内容时保留其他专区关联、各自排序、来源说明及未展示的同类型属性。已有不属于当前角色选项的值明确标为“保留已有值”。
- 一级角色切换、二级类别往返保留编辑缓存；新资源未勾选其他专区时，不因切换过程自动向其他角色发布。
- 类型改变时不携带不兼容属性。明确清空或取消展示的选择会保存。
- 专区排序在“其他展示设置”中维护。角色列表显示当前专区排序，全部资源列表显示资源本身排序。

## 数据库、接口与部署

**不改表，不新增迁移 SQL，不重复执行 000～003，不修改小程序代码。** 复用 content_resource、content_resource_view 和 JSON attributes。演示数据快照和分类字典不改。

管理接口新增支持 GET /admin/api/resources?audience=investor&category=project，角色分类过滤复用已有查询逻辑，管理端仍显示草稿、已发布、已下架；公共接口与权限边界保持原契约。

更新云端需在 yiyaodemo 管理服务部署包含本次修改的后端版本，APP_MODE=admin。原小程序服务无需因本次管理界面改动单独更新。环境变量和管理员密码哈希保持原配置。
